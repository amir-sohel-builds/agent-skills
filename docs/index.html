Skills Trust GitHub

TPM tools that run, not advice.

Sixteen skills for planning, running, and reporting programs. Each takes a real input and produces a real artifact. Works with Claude Code and Cursor.

git clone https://github.com/amir-sohel-builds/agent-skills.git && cd agent-skills && bash install.sh

Installs into ~/.claude/skills, and ~/.cursor/skills if you have it. Read install.sh before you run it.

One command, one artifact

This is a real run of risk-register on its bundled example, trimmed to the part that matters.

skills/risk-register
$ python3 scripts/risks.py --input risks.json --output RISKS.md

## Top risks (score 15 or more)
- R1 Database cutover fails and checkout goes down (score 20, owner: Sam)

## Flags
- R3 has no owner
- R3 has no mitigation

## Closed
- R4 Teams keep using the old dashboard (score 4)

The tool does the arithmetic and names what is missing. It never judges likelihood or impact. The owner sets those numbers, because that is a human call.

If it cannot be run, it is not in this repo.

Every skill has exact inputs, one exact command, and one exact output. What needs human judgment is named as human judgment, not hidden inside the tool.

Each skill lives in one folder with a fixed SKILL.md: Inputs, Run, Output, Rules, and What it does not do. The script is the skill. The file tells you how to run it and how to read what comes out.

The sixteen

Plan it

Scope the work before it starts.

  • scope-planTurns a vague request into a scoped plan, then checks the plan is complete.
  • dependency-mapFinds cycles, orphans, and the critical path from work items.
  • capacity-planMatches committed work against capacity, by person and week. Flags over-allocation.
  • risk-registerScores risks by likelihood times impact, sorts them, flags the top ones.

Run it

Keep the program honest while it moves.

  • status-rollupRolls workstreams into one honest status page, blockers named.
  • stakeholder-updateTurns the same status file into a one-page exec update. Risks first.
  • decision-logLogs decisions with date, context, and decider. Lists what is still open.
  • launch-readinessEvaluates a launch checklist. GO only when every required item is yes.

Prove it

Show the work, with data you can trust.

  • weekly-flashTurns the week's shipped work into a one-page flash report.
  • release-notesTurns merged work since the last tag into human release notes.
  • report-trust-checkAudits the data behind a report: stale rows, missing values, duplicates.
  • retro-packAssembles a retro from the week's facts: shipped, broken, still blocked.
  • pr-reviewerReviews pull requests for secrets and dangerous patterns before a human approves. Ships as a GitHub Action.

Lead it

The same discipline, across teams.

  • quarterly-planBuilds a quarter plan across teams: load, cross-team dependencies, ordering checks.
  • decision-reviewGrades open decisions: decider, context, alternatives, reversal criteria.
  • exec-review-packBuilds a one-page exec review from status, risks, and decisions.

Built to be trusted

Tested

Every skill runs against its examples. python3 evals/run_evals.py checks all sixteen, tests the installer, and exits 1 on any failure. A skill that fails is not shipped.

Scanned

The repo was security audited, with no Critical or High findings. The evals run the same scanner as pr-reviewer over the whole repo and fail on either.

Self-reviewing

pr-reviewer is deployed on this repo. It reviews every pull request and scans the repo nightly. Open the Actions tab to watch it run.
