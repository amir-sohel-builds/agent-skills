agent-skills

A TPM suite. Sixteen tools that run.

Tools I use to run programs, built so any TPM can use them at any company. Each skill does one job, takes a real input, and produces a real artifact. No advice dressed as a tool. Every skill ships a script. If it cannot be run, it is not in this repo. Examples use real team sizes, not toy ones.

git clone https://github.com/amir-sohel-builds/agent-skills.git && cd agent-skills && bash install.sh

§01 Plan it

The ones that scope the work

scope-plan

Turns a vague request into a scoped plan, then checks the plan is complete.

dependency-map

Builds a dependency map from work items. Finds cycles, orphans, and the critical path.

capacity-plan

Matches committed work against team capacity, by person and by week. Flags over-allocation.

risk-register

Scores risks by likelihood times impact, sorts them, and flags the top ones.

§02 Run it

The ones that run the program

status-rollup

Rolls up workstreams into one honest status page, blockers named.

stakeholder-update

Turns the same status file into a one-page exec update. Risks first.

decision-log

Logs decisions with date, context, and decider. Lists what is still open.

launch-readiness

Evaluates a launch checklist. GO only when every required item is yes.

§03 Prove it

The ones that show the work

weekly-flash

Turns the week's shipped work into a one-page flash report.

release-notes

Turns merged work since the last tag into human release notes.

report-trust-check

Audits the data behind a report: stale rows, missing values, duplicates.

retro-pack

Assembles a retro pack from the week's facts: shipped, broken, still blocked.

pr-reviewer

Reviews a pull request for secrets, dangerous patterns, and quality issues, before a human approves it. Ships as a GitHub Action. Lives in tools-and-automation.

§04 Lead it

The ones that work at org scale

quarterly-plan

Builds a quarter plan across teams: load against capacity, cross-team dependencies, ordering checks.

decision-review

Grades open decisions for quality: decider, context, alternatives, reversal criteria.

exec-review-pack

Builds a one-page exec review pack from status, risks, and decisions.

Evals

Every skill is tested

Run python3 evals/run_evals.py. It runs all sixteen skills against their examples, checks their outputs, tests the installer, and checks the whole repo for company info. A skill that fails its eval is not shipped.

Tools and automation

The action runs itself

The PR reviewer lives in tools-and-automation/ and is already deployed in this repo. It reviews every pull request, and it scans the repo itself every night at 02:00 UTC. To see it run right away, open the Actions tab, select PR Reviewer, and click Run workflow.

Security

Scanned before it ships

The repo is audited and clean, see SECURITY.md. The evals run the pr-reviewer scanner over the whole repo and fail on any Critical or High finding. The same scanner ships as a GitHub Action, so any repo can review every pull request before a human approves it.

How a skill works

One folder, one job, one script

Each skill lives in skills/<name>/ and has a SKILL.md file in a fixed shape: Inputs, Run, Output, Rules, and What it does not do. The script lives under scripts/ and the worked example under examples/. The script is the skill. The SKILL.md tells you how to run it and how to read what comes out.

Claude Code picks up skills from ~/.claude/skills. After installing, just describe the job, for example “roll up this week's status from workstreams.json”, and the matching skill loads. The same files work in Cursor from ~/.cursor/skills.
